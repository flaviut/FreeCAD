1 low severity 12 cluster-0002 (1 findings)

User workflow: On Linux using FreeCAD with Coin configured for EGL, open or create a document, then use View -> Save picture..., select the image method Offscreen (old), choose an output file, and confirm. This invokes Coin's legacy offscreen renderer. There is no normal FreeCAD UI path that deliberately makes eglBindAPI(EGL_OPENGL_API) fail; the leak is only exercised when the EGL environment initializes far enough to reach that bind call but rejects the OpenGL API.

Reproduction:

  1. 1. Start FreeCAD in an EGL-backed environment where EGL display initialization succeeds but binding EGL_OPENGL_API is unsupported or fails, such as a misconfigured or incompatible EGL/driver setup.
  2. 2. Create a new document or open an existing FreeCAD document containing visible geometry.
  3. 3. Choose View -> Save picture... (the command may be labeled Save image... in some translations).
  4. 4. In the image options, select Offscreen (old), choose a writable image filename, and confirm the save.
  5. 5. Repeat the save operation several times while monitoring FreeCAD's diagnostic output or process memory; each failed EGL bind attempt leaves the allocated offscreen context data unreleased.

User-visible effect: The image save fails or produces no image when the EGL API bind fails, while FreeCAD may remain running. Repeated attempts can gradually increase the process memory usage; diagnostic output reports that eglBindAPI(EGL_OPENGL_API) failed.

Recommended action: In the EGL offscreen context creation failure branch, call eglglue_contextdata_cleanup(ctx) before returning NULL. Add a regression test or fault-injection test for eglBindAPI failure, and consider using the newer Qt offscreen renderer instead of the legacy Offscreen (old) method.

2 low severity 3 cluster-0001 (1 findings)

User workflow: In the Robot workbench, a user can choose Robot > Trajectory to create a trajectory, use Robot > Insert in Trajectory to add waypoints, and use Robot > Trajectory Compound or Robot > Dress-Up Trajectory to combine or modify trajectories. These normal UI workflows do not provide a trajectory-clone command and do not expose a way to force a child clone or add operation to fail. No normal FreeCAD UI path exists for reproducing this leak; a custom extension or diagnostic build that invokes trajectory cloning is required.

Reproduction:

  1. Open FreeCAD and switch to the Robot workbench.
  2. Create a trajectory with Robot > Trajectory, add multiple waypoints with Robot > Insert in Trajectory, and optionally create a second trajectory.
  3. Use Robot > Trajectory Compound or Robot > Dress-Up Trajectory, then recompute, simulate, or export the result.
  4. Observe that these standard operations do not expose trajectory cloning and do not reproduce the reported allocation leak.
  5. To reproduce the defect, use a custom plugin or diagnostic build that clones a composite trajectory and makes a child clone or insertion fail; this cannot be performed through the normal FreeCAD UI.

User-visible effect: There is no directly observable effect during normal Robot workbench use. When the unavailable cloning operation is invoked and a child operation throws, the partially created trajectory remains allocated until process termination, so repeated failures in an extension or internal caller can increase FreeCAD memory usage and eventually degrade or terminate the session.

Recommended action: Replace the raw composite allocation in the clone operation with exception-safe ownership, or explicitly destroy it on every failure path before rethrowing. Add a regression test that forces a child clone or insertion failure and verifies cleanup.

3 low severity 2 cluster-0003 (5 findings)

User workflow: There is no Mesh workbench operation that reaches this allocation: Mesh workbench Union, Difference, Intersection, Evaluate and Repair, Evaluate Solid, and the mesh editing commands operate on Mesh::Feature data and do not invoke SMESH_MeshEditor downward connectivity. The closest user-visible SMESH workflow is MeshPart workbench -> Mesh From Shape: select a Part solid or compound containing a volumetric region, choose Netgen or another SMESH method, optionally enable second-order elements, and create the mesh. That workflow creates an internal SMESH mesh and can produce quadratic wedges or hexahedra, the input shapes corresponding to the leaked SMDS_DownQuadPenta and SMDS_DownQuadHexa allocations, but the traced FreeCAD path does not call BuildDownwardConnectivity. A Python-console step is required to attempt a direct trigger, and the current public FreeCAD Python API does not expose the SMESH_MeshEditor operation that calls this builder.

Reproduction:

  1. Open FreeCAD and switch to the MeshPart workbench.
  2. Create or open a Part solid with a volumetric interior, then choose Mesh From Shape and select the solid.
  3. Choose a SMESH-based mesher such as Netgen, enable second-order elements if available, and create the mesh.
  4. Repeat meshing and close/delete the generated mesh while monitoring process memory; this exercises SMESH mesh creation and destruction but does not, by itself, build the downward-connectivity cache.
  5. To exercise the confirmed leak itself, a custom C++/SMESH integration step is required to call SMESH_MeshEditor functionality that invokes BuildDownWardConnectivity(true) on a mesh containing quadratic wedge or hexahedral volume cells, then destroy the SMDS mesh without calling CleanDownwardConnectivity().

User-visible effect: No reliably reproducible effect is exposed through the current Mesh or MeshPart workbenches. When the unexposed downward-connectivity path is invoked repeatedly by an integration or plugin, process memory grows because the per-cell-type SMDS_Downward objects remain allocated after SMDS_UnstructuredGrid destruction; a long-running process can eventually suffer memory pressure.

Recommended action: Fix SMDS_UnstructuredGrid destruction to release every _downArray entry, preferably by invoking the existing CleanDownwardConnectivity() cleanup path, and add a regression test that builds downward connectivity for quadratic wedge and hexahedral cells before destroying the mesh. Also confirm whether the unused SMESH editor path is intended to remain shipped; if not, remove or isolate it rather than treating ordinary Mesh workbench workflows as affected.
