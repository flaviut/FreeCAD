# GUI dialog policy audit

This is a source-level baseline against the [GUI dialog policy](GuiDialogPolicy.md),
not a claim that every listed finding has the same user impact. It is intended to make
dialog cleanup selectable and reviewable rather than to require one large refactor.

## Summary

Of 153 in-scope or unresolved dialogs, 7 pass the
static policy, 145 have at least one actionable finding, and
1 need focused human review. The audit records 399
findings: 77 high, 261 medium, and
61 low severity. Another 61 discovery candidates were
excluded or identified as duplicate representations.

## Cross-cutting priorities

1. Correct parent relationships first. The audit found 72 dialogs with a parenting
   violation, dominated by Python `loadUi()` calls that omit a parent and sometimes add
   manual centering as compensation. Pass the narrowest owning widget, falling back to the
   main window for application-level dialogs.
2. Add keyboard semantics while touching each form. Keyboard or accessibility findings
   affect 115 dialogs, most often labels without buddies or translated mnemonics.
3. Replace fixed constraints and manual placement with layout behavior. Layout findings
   affect 73 dialogs. Explicit initial geometry is allowed and is not itself a finding.
4. Consolidate standard actions into `QDialogButtonBox` and remove theme-like styling.
   Native-control findings affect 34 dialogs and are usually local changes.

These counts overlap: a dialog can appear in several categories. Work can therefore proceed
module by module without making the baseline a single all-or-nothing cleanup project.

## Findings

Severity is triage guidance. High findings affect window relationships or broadly block
use; medium findings affect resizing, semantics, or keyboard access; low findings are
localized consistency improvements. Verify a finding at the cited source before changing
code because this audit is a point-in-time static analysis.
